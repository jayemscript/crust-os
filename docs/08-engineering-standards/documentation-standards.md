# Documentation standards

Write for a developer learning the system while building it. Put the main explanation in one canonical page and link to it from roadmaps and phase plans. Use relative links within the repository and descriptive link text.

Label **Fact**, **Proposal**, **Assumption**, and **Open question** where confusion could affect implementation. Give facts an authoritative citation and relevant revision; state the scope of observations. Mark incomplete features as Not Started even when their plans are detailed.

For a phase update, include the goal, dependencies, design, expected files, risks, validation steps, acceptance criteria, actionable checkboxes, and current status. Progress reports must say what changed, what was observed, and what remains unverified. Use [decision records](../09-project-management/decision-log.md) for consequential choices and [changelog](../09-project-management/changelog.md) for material documentation changes.
