# Contributing

The project is in a documentation-only foundation stage. Corrections, clearer explanations, and cited research are welcome. Do not introduce implementation code, a build system, dependencies, or generated artifacts without explicit authorization for a specific phase.

## Working agreement

1. Read the [overview](README.md), [architecture](docs/03-system-architecture/architecture-overview.md), relevant [phase](docs/README.md#development-phases), and [open questions](docs/06-research/open-questions.md).
2. Describe whether a statement is a verified fact, proposal, assumption, or question. Cite primary references where practical and record the version or revision consulted.
3. Keep changes scoped to the task. Update the relevant phase plan and [decision log](docs/09-project-management/decision-log.md) when a choice affects later work.
4. Use actionable Markdown checkboxes and the [status vocabulary](docs/09-project-management/progress-tracker.md). Do not mark a feature complete before its acceptance evidence exists.
5. Review navigation, technical claims, and generated-file hygiene using the [review checklist](docs/08-engineering-standards/review-checklist.md).

Future code contributions should follow [AGENT.md](AGENT.md), the [coding standards](docs/08-engineering-standards/coding-standards.md), and the authorized phase boundary.
